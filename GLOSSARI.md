### Backlog

- Inglés: backlog
- Definición: Es la lista de tareas pendientes que tenemos que hacer en un proyecto.
- Ejemplo: Al principio pusimos los ocho issues en Backlog.

### Clonación

- Inglés: clone
- Definición: Es copiar un repositorio de GitHub a nuestro ordenador para trabajar con sus archivos.
- Ejemplo: Utilizamos git clone para descargar nuestro fork de Flask.

### Commit

- Inglés: commit
- Definición: Es guardar los cambios que hemos hecho en Git, con un mensaje para saber qué hemos modificado.
- Ejemplo: Hicimos un primer commit en nuestra rama develop.

### Fork

- Inglés: fork
- Definición: Es una copia de un repositorio que hacemos en nuestra cuenta de GitHub, sin cambiar el original.
- Ejemplo: Hicimos un fork del repositorio pallets/flask.

### Git

- Inglés: Git
- Definición: Es un sistema de control de versiones que nos permite guardar los cambios de un proyecto.
- Ejemplo: Utilizamos Git para hacer commits y trabajar con ramas.

### GitHub Projects

- Inglés: GitHub Projects
- Definición: Es una herramienta de GitHub que sirve para organizar las tareas de un proyecto.
- Ejemplo: Creamos un proyecto para organizar los ocho issues de la práctica.

### Issue

- Inglés: issue
- Definición: Es una tarea que creamos en GitHub para indicar qué tenemos que hacer y cuándo estará terminada.
- Ejemplo: Creamos un issue para instalar Flask y preparar la base de datos.

### Iteración

- Inglés: iteration
- Definición: Es un periodo de tiempo en el que organizamos las tareas que vamos a realizar.
- Ejemplo: Repartimos los ocho issues entre dos iteraciones de tres semanas.

### Kanban

- Inglés: Kanban
- Definición: Es un tablero con columnas que nos ayuda a ver qué tareas tenemos pendientes y cuáles estamos haciendo.
- Ejemplo: Nuestro tablero tiene las columnas Backlog, Sprint Backlog, In Progress, In Review y Done.

### Origin

- Inglés: origin
- Definición: Es el nombre que normalmente utiliza Git para identificar el repositorio remoto de nuestra copia.
- Ejemplo: En nuestra práctica, origin apunta a nuestro fork de Flask en GitHub.

### Pull

- Inglés: pull
- Definición: Es un comando que sirve para traer los cambios del repositorio remoto a nuestro ordenador.
- Ejemplo: Podemos hacer git pull para tener en casa los cambios que subimos desde el instituto.

### Push

- Inglés: push
- Definición: Es un comando que sirve para subir nuestros commits al repositorio remoto.
- Ejemplo: Utilizamos git push para subir nuestros cambios a GitHub.

### Rama

- Inglés: branch
- Definición: Es una línea de trabajo dentro de un repositorio que nos permite hacer cambios sin modificar otra rama.
- Ejemplo: Creamos la rama develop para trabajar en la práctica.

### Sprint

- Inglés: sprint
- Definición: Es un periodo corto de trabajo en el que intentamos completar unas tareas determinadas.
- Ejemplo: Organizamos la práctica en dos sprints de tres semanas.

### Status

- Inglés: status
- Definición: Es el estado en el que se encuentra una tarea dentro de GitHub Projects.
- Ejemplo: Pusimos las cuatro tareas del primer sprint en Sprint Backlog.

### Upstream

- Inglés: upstream
- Definición: Es el nombre que podemos poner al repositorio original del que hicimos nuestro fork.
- Ejemplo: En nuestra práctica, upstream apunta al repositorio original pallets/flask.
